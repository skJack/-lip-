# 跟着 H3 学视频生成 · 第二期 · 信息流 · HTML PPT 使用说明

打开方式：用 Chrome 直接打开 `deck.html`（双击即可）。整份 deck 就这一个文件，图全是 SVG 现画的，没有图片文件，不需要联网。

按键和第一期一样（这个系列比仓库里 VLA、世界模型两个系列的 deck 早，按键不一样）：

- `→` `空格` `↓` `Enter` `PageDown` 或鼠标单击：下一步——**同一页里先一个个放出动画，放完才翻到下一页**
- `←` `↑` `PageUp`：上一步（先收回本页的动画，收完回到上一页）
- `Home` `End`：首页 / 末页
- 画布固定 1280×720，按窗口等比缩放；全屏用浏览器自己的全屏（Mac `⌃⌘F`，Windows `F11`）
- 没有页面列表，也不支持 `deck.html#10` 这种地址跳页

配色全系列通用：紫色 = 文本，橙色 = 视频（橙色虚线框 = 条件帧），绿色 = 音频。

页码对应讲什么：

| 页 | 标题 | 内容 |
|---|---|---|
| 1 | 封面 | H3 模型信息流 |
| 2 | H3 是什么 | 33B、50 层单流 transformer；视频和音频一次生成（768p · 24fps + 32kHz 立体声）；4–15 秒、六种画幅；开源的两个 checkpoint FL2VA / Ref2VA 结构相同、只有权重不同；Artificial Analysis 视频编辑 #1、文生视频 #2、图生视频 #3；没有论文，讲的都来自开源代码 |
| 3 | 什么是「条件」 | 一句话、首帧、首尾帧、参考图、要改的源视频——给模型的每样「要求」都叫条件，右边标着各归哪个 checkpoint |
| 4 | 之前：两条流，一座桥 | 对照组 Wan2.2：条件帧和噪声在通道上拼成 36 通道；文本单独一条流，每一层靠 cross-attention 单向读文本；右边是对照源码核对的四条结论 |
| 5 | H3：拼成一条 | 文本 512 行 + 条件 + 音频 414 行 + 目标视频 37,296 行，`index_copy` 拼成 39,230 × 5376 的一条序列；此后不再区分模态，零 cross-attention |
| 6 | 一图走完 | 首帧图 + 一句话 → 5 秒有声视频的全流程：编码成行 → 拼一条 → 50 层自注意力 → 两个头出速度 → 8 步 → 两个 VAE 解码 |
| 7 | 一切成行 | 四种原料各自怎么变成「行」、每种多少行、每行多少维；视频行占 95%，视频生成贵就贵在这 |
| 8 | 维度对齐 | 三个线性层把 96 / 32 / 5120 维统一到 5376；只有文本多过两层 token refiner |
| 9 | Attention | 一个视频 patch 同时看文本（内容）、条件（长相）、音频（音画同步），音频也反过来看画面；代价是 39,230² ≈ 15 亿对分数，attention 占算力八成 |
| 10 | 出口 | 两个输出头对每一行都算一遍，再按身份挑：文本行丢掉、条件行必须手动扔掉、音频头和视频头各出速度；5 秒片 4×H100 实测 13 秒出 |
| 11 | 拼在一起，值不值 | 好处：加条件只改拼法不改架构、音画同步是原生的、形态和 LLM 一样；代价：序列长、文本行和条件行每步都要重新过 50 层。留给后两期的问题：模型内部不分模态，它怎么知道谁是参考、谁该生成 |

每个数字的出处（行数怎么算出来的、Wan2.2 的桥是不是每层都有、条件行为什么要手动扔）见 `../notes/技术事实核查.md`。
