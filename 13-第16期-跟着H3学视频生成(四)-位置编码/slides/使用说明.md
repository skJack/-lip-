# 跟着 H3 学视频生成 · 第四期 · 位置编码 · HTML PPT 使用说明

打开方式：用 Chrome 直接打开 `deck.html`（双击即可）。整份 deck 就这一个文件，图全是 SVG 现画的，没有图片文件，不需要联网。

按键和前三期一样（这个系列比仓库里 VLA、世界模型两个系列的 deck 早，按键不一样）：

- `→` `空格` `↓` `Enter` `PageDown` 或鼠标单击：下一步——**同一页里先一个个放出动画，放完才翻到下一页**
- `←` `↑` `PageUp`：上一步（先收回本页的动画，收完回到上一页）
- `Home` `End`：首页 / 末页
- **左上角有一排页码按钮**：平时几乎透明，鼠标移过去才显出来，点哪个跳哪页
- 画布固定 1280×720，按窗口等比缩放；全屏用浏览器自己的全屏（Mac `⌃⌘F`，Windows `F11`）

配色和前两期一样：紫色 = 文本，橙色 = 视频，绿色 = 音频。**注意**：这期坐标里的「t 轴」是时间位置（第几帧、第几秒），和第三期的噪声水平 t 是同一个字母、不同的东西。

页码对应讲什么：

| 页 | 标题 | 内容 |
|---|---|---|
| 1 | 封面 | 位置编码 |
| 2 | attention 不包含顺序信息 | 把序列随便打乱，每一对的注意力分数一个都不变；所以要把位置写进每一行——绝对位置编码 vs 相对位置编码，主流选相对 |
| 3 | RoPE · 按位置旋转向量 | 第 p 个位置转 p·θ 度；q·k = cos(夹角)，代入后只剩内容差和位置差，绝对位置消掉了——这就是「相对」位置编码 |
| 4 | 一个 token = 64 个向量对 | 「今天天气真好」里的两个「天」没有位置编码时一模一样；128 维两两分组成 64 对，每对转速不同（示意 57° / 5.7° / 0.057° 每格），快的管近处、慢的管远处 |
| 5 | RoPE 的计算 | 维度两两配对 → 每对做二维旋转 → θᵢ = 10000^(−2i/d)，右边是对应的几行代码；只转 Q 和 K，不转 V |
| 6 | 视频的位置是三个数 | 文本的位置是一个数，视频是 (t, h, w) 三个数；每个头的维度分三份、各按一个轴转 = 3D RoPE，视频模型的通用做法（Wan 同款） |
| 7 | 统一时间轴 | H3 特殊设计 ①：文本、条件、音频、视频排进同一根 t 轴，1 格 = 1/40 秒，t = 512 + 时刻(秒) × 40；同一时刻的视频帧和音频格坐标相同，音画同步由此而来；条件行钉在第 1 帧的坐标 |
| 8 | 留 32 维不转 | H3 特殊设计 ②：每个头 128 维里 t / h / w 各转 32 维，剩下 32 维直通不转，留给「距离远但必须强关联」的行对（第 1 帧和第 37 帧里同一张脸、prompt 里的「猫」和画面里的猫） |
| 9 | 四期串起来 | 四期各一句：训练方法、序列结构、模态与阶段区分、时空定位；H3 的任务和模态区分不靠专门模块，靠每行的三个标签——模态 tag、噪声水平 t、时空坐标 |

第 7 页图上的视频行按像素帧画（间距均匀，方便看对齐）；实际进模型的是 VAE 压缩后的 latent 帧，第 1 个占 1.67 格、之后每个占 6.67 格，对齐关系不变——页面下方那行小字说的就是这个。每个数字的出处见 `../notes/技术事实核查.md`。
