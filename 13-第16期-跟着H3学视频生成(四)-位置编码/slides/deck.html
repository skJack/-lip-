每一对的注意力分数完全不变：「猫追狗」与「狗追猫」无法区分 · 第 1 帧与第 37 帧对调，输出不变
必须把位置信息写进每一行的向量 —— 这就是位置编码
绝对位置编码
每个位置配一个位置向量，加进 token（Transformer 原始做法）· 编码的是「在第几格」
相对位置编码
让注意力分数直接依赖「两行隔多远」· 编码的是「隔几格」——语言和视频真正需要的关系
当前主流选相对 · RoPE = 用旋转实现的相对位置编码 —— 下一页
位置编码 ②

RoPE · 按位置旋转向量

RoPE 的优势：纯旋转，零参数 同一对关系放在序列任何位置，分数相同 序列变长，规则不变 以上在一对维度上推导 · 128 维的做法见下页

128 维两两分组 = 64 个向量对 · 每对是平面上一个箭头，各有自己的转速 θᵢ（示意取 3 对）
快对：1 格就差很多 → 管近距离 · 但十几格就绕回一圈 慢对：上万格不绕回 → 管远距离 · 但近处几乎不动 64 对从快到慢 → 近中远全覆盖 · 总分 = 64 个 cos 相加
位置编码 ② · 深入

RoPE 的计算

① 维度两两配对
d₀ d₁ d₂ d₃ d₄ d₅ … d₁₂₆ d₁₂₇ 128 维 → 64 对 · 每对 = 平面上一个点
② 每对做二维旋转（角度 = 位置 p × 转速 θᵢ）
x₁' = x₁·cos(p·θᵢ) − x₂·sin(p·θᵢ) x₂' = x₁·sin(p·θᵢ) + x₂·cos(p·θᵢ)
纯三角函数 · 没有可学习参数
③ 64 对转速不同
θᵢ = 10000^(−2i/d)
i 小 → 转得快 → 对近距离敏感 · i 大 → 转得慢 → 负责远距离
freqs = 1 / 10000**(arange(0, d, 2) / d) # 64 个转速，前快后慢 ang = pos * freqs # pos = 这一行排第几（0,1,2,…） # 每对的角度 = 位置 × 各自转速 x1, x2 = x[..., 0::2], x[..., 1::2] # 拆成 64 对 x_rot = cat([x1*cos(ang) − x2*sin(ang), x1*sin(ang) + x2*cos(ang)]) # 逐对旋转
只旋转 Q 和 K · V 不转 q·k 打分时角度相减：p₂θ − p₁θ → 绝对位置消掉，只剩位置差 以上 = 一维 RoPE：位置是一个数（第几个 token）

位置编码 ④ · H3 特殊设计 ①

统一时间轴

H3 特殊设计 ①：文本、条件、音频、视频全排进同一根 t 轴，1 格 = 1/40 秒 · 一条公式：t = 512 + 时刻(秒) × 40　→　视频第 k 帧 = 512 + k·5/3 · 音频第 n 格 = 512 + n
实际进模型的是 VAE 压缩后的 latent 帧：第 1 个占 1.67 格、其后各占 6.67 格——对齐关系不变
同一时刻 → 同一坐标 → 音画同步由位置编码直接提供 条件行坐标 = 第 1 帧坐标 → 位置上硬锚定 左右声道位于 w 轴两端 → 编码空间方位
位置编码 ⑤ · H3 特殊设计 ②

留 32 维不转

t 轴 32 维⟳ 按第几帧转
h 轴 32 维⟳ 按第几行转
w 轴 32 维⟳ 按第几列转
不转 32 维直通 · 不含位置信息
旋转的维：分数随距离变化
内容相同的两行：
隔 0 格 → +1.0
隔 3 格 →  0.0
隔 6 格 → −1.0（抑制！）
直通的维：匹配不受距离影响
第 1 帧的脸 ↔ 第 37 帧的脸
prompt 的「猫」 ↔ 画面里的猫
拼成一条长序列 → 大量「距离远、但必须强关联」的行对 → 必须保留直通维（Wan 128 维全转：文本不在坐标轴上，无此问题——两处设计相互配套）
