# π0.5: a Vision-Language-Action Model with Open-World Generalization

> 对应「可lip」VLA 入门第 22 期（二）视频。论文：[arXiv:2504.16054](https://arxiv.org/abs/2504.16054)。
> 这是我读论文时的整理笔记：数字都来自论文正文或图表，标了「估读」的是从没有数值的柱状图上估的；看图请对照 arXiv 上的原文。

- arXiv: 2504.16054（v1 2025-04-22，本地 PDF 为 v1；CoRL 2025）· 机构: Physical Intelligence · 代码/权重: 已开源——openpi 提供 `pi05_base` 及 DROID / LIBERO fine-tuned checkpoint（JAX + PyTorch）· 项目页: https://pi.website/blog/pi05
- 一句话: 在 π0 基础上改成"先用 FAST 离散 token 做异构 co-training 预训练、再加 flow action expert 做 post-training"的混合配方，同一个模型先预测语义 subtask 再出动作，用约 400 小时移动操作数据 + 大量其他机器人/网页/高层标注数据，第一次让端到端 VLA 在从未见过的真实家庭里完成 10–15 分钟的厨房/卧室清理。

## 1. 要解决的问题

VLA 基本都在与训练数据相近的环境里评测，开放世界泛化没人证明过。简单技能（抓取、开抽屉）可以靠在更多环境采数据硬堆，但"清理一个陌生厨房"这种长程任务，靠采集覆盖是不可能的。作者的假设：泛化要靠从异构来源迁移知识——其他机器人的动作数据、语义 subtask 预测、网页图文、人类口头指令——而 VLA 把所有模态都放进同一个序列建模框架，正好能做这种 co-training。另一条线索来自 FAST：离散 token 训练快、语言跟随好，但自回归推理慢；flow 推理快但训练慢——需要两者兼得。

## 2. 方法

**架构（Sec. IV-A，Appendix E）。** 仍是 PaliGemma 2B VLM + 300M action expert（维度与 π0 相同）。模型表示 π_θ(a_{t:t+H}, ℓ̂ | o_t, ℓ)，分解为 π_θ(a | o_t, ℓ̂)·π_θ(ℓ̂ | o_t, ℓ)：ℓ 是总任务 prompt（"把餐具放进水槽"），ℓ̂ 是文本输出——既可以是预测的 subtask（"pick up the plate"），也可以是网页 VQA 的答案。动作分布只依赖 ℓ̂ 不依赖 ℓ。与 π0 的差别：本体状态离散化后当文本 token 输入；flow 时间步 τ 通过单独 MLP + adaptive RMSNorm 注入 action expert 每一层（π0 是拼进动作嵌入）；attention mask 里 FAST 动作 token 对前缀双向、自身因果，action expert 看前缀和自身但**不看 FAST token**（避免两种动作表示互相泄漏），VLM 侧任何 token 都不看 action expert。H = 50，10 步去噪。

**双动作表示与损失（Eq. 1）。**
E[ H(x_{1:M}, f^ℓ_θ(o_t, ℓ)) + α‖ω − a_{t:t+H} − f^a_θ(a^{τ,ω}, o_t, ℓ)‖² ]
第一项是文本 token（含 FAST 编码的动作 token）的交叉熵，第二项是 flow matching。预训练 α=0（纯自回归 VLM，稳定、快、语言好），post-training α=10 并随机初始化 action expert。

**预训练数据（Sec. IV-C，Fig. 4）。** MM：约 400 小时移动操作机器人在约 100 个家庭里的家务数据（与评测最相关）；ME：单/双臂固定机械臂在更多家庭里的数据（不同 embodiment，但轻便所以场景更多）；CE：实验室 cross-embodiment 数据（π0 数据集的扩展版 + OXE）；HL：对 MM/ME/CE 的多阶段任务人工标注 subtask 文本，训练模型先预测相关 bounding box 再预测 subtask 再出动作；WD：CapsFusion、COCO 图说，Cambrian-7M、PixMo、VQAv2 问答，以及扩充了室内场景/家居物品的检测数据。第一阶段 97.6% 的样本不是移动操作机器人做家务的数据。动作统一预测目标关节和末端位姿，prompt 里加 `<control_mode> joint/end effector` 区分；按 1%/99% 分位归一化到 [−1,1]，维度 pad 到最大。预训练 280k 步。

**Post-training（Sec. IV-D）。** 80k 步。动作数据只用 MM + ME 中成功且长度低于阈值的 episode；保留 WD 维持语义能力；保留多环境的 HL；新增 VI（verbal instruction）：专家用"语言遥操作"——实时给已训好的低层策略发 subtask 指令完成任务——录下的高层示范，只占 MM 高层样本的约 11%。

**推理与系统（Sec. IV-E）。** 每步先自回归采样 subtask ℓ̂（用全部 4 路相机），再以 ℓ̂ 为条件做 10 步去噪出 50 步 chunk（用手腕 + 前视相机）。两种移动操作平台：两条 6-DoF 臂 + 平行夹爪 + 全向底盘 + 躯干升降，18–19 维状态/动作，50 Hz 目标位姿/底盘速度由 PD 控制器跟踪，没有任何规划或碰撞检测。

## 3. 实验

所有评测都在训练中没见过的环境：3 个真实家庭 + 若干 mock 厨房/卧室（Fig. 6）。任务与 rubric（Appendix B）：dishes in sink（4 件，满分 8）、items in drawer（满分 4）、laundry basket（满分 3）、make bed（满分 5）；每策略每任务 10 次，标准比较共 40 次/策略，显著性用双侧 t 检验。

- **真实家庭（Fig. 7b）：** 三个家的 7 个任务/环境组合，task progress 估读约 65–92%，与 mock 环境水平相当，作者据此认为 mock 评测有代表性。任务 2–5 分钟，只给"place the dishes in the sink"这类高层指令。
- **环境数量 scaling（Fig. 8）：** 只变 MM 数据的地点数（3/12/22/53/82/104，40k 步控制样本量）：平均 progress 估读从 ≈13% 涨到 ≈87%（82 地点处回落到 ≈67%）。104 地点模型 ≈ 直接在测试家庭训练的对照（≈82%）；而不做 co-training 预训练、只用测试家庭数据 ≈38%，只用 104 地点数据且无预训练 ≈5%——说明其他数据源比"见过测试环境"更重要。
- **语言跟随随地点数（Fig. 9）：** in-distribution 物体的 follow rate 估读 ≈25%→≈68%，OOD 类别 ≈15%→≈62%（对照：不听指令的策略应约 20%，Appendix C）。
- **数据配比消融（Fig. 10/11）：** 完整 π0.5 ≈78%；no WD ≈73%（p=0.385，不显著）；no CE ≈50%、no ME ≈53%、no ME or CE ≈40%（均 p<0.001）。但在语言跟随上 no WD 对 OOD 物体伤害很大（OOD 成功率估读 ≈93%→≈72%），作者推测网页数据带来了对未见物体类别的理解。
- **vs π0（Fig. 12）：** 相同 cross-embodiment 数据、可比步数。π0.5 显著优于 π0（80k 及 300k 步）和 π0-FAST+Flow（混合配方但无 HL/WD）。估读 dishes in sink：≈92% / ≈55% / ≈42%（π0 300k）/ ≈18%（π0 80k）。语言跟随上 π0.5 > π0-FAST+Flow ≫ π0（Fig. 16），说明离散 token 训练对语言跟随的贡献。
- **高层推理消融（Fig. 13，最有信息量）：** 完整 π0.5 ≈78%；implicit HL（训练含 HL 数据但推理不显式出 subtask）≈70%，p=0.144 不显著；no HL（训练也不含）≈62%；no VI ≈60%；no WD ≈60%；GPT-4 做高层 ≈57%（最差，p=0.002）；human HL ≈63%（p=0.016）——模型自己的高层竟高于人类 oracle。解读：显式 subtask 推理有收益，但大部分收益来自把 subtask **预测**数据放进训练；仅占 11% 的 VI 数据不可或缺。

## 4. 局限

作者承认（Sec. VI）：会犯错——陌生的抽屉把手、物理上难开的柜门；部分可观测（机械臂挡住要擦的污渍）；高层容易"分心"（反复开关抽屉）；prompt 简单，能处理的指令复杂度由标注决定；上下文短、没有记忆，跨房间导航或记住物品放哪做不了。我读出来的：(1) 评测任务都是训练分布内的任务类别，泛化的是环境和物体而非任务；(2) 每步都先解码 subtask 文本，延迟高于 π0（RTC 论文给出 π0.5 在 4090 上 5 步去噪为 76 ms）；(3) 消融里 GPT-4 只给了标签列表而非精心设计的 harness，结论对"frontier model 做高层"未必公平。

## 5. 复现要点

- 开源：openpi `pi05_base`（预训练 + post-training 后的基座）、`pi05_droid`、`pi05_libero`；训练/推理代码含 LoRA 与全量微调。预训练数据（MM/ME/CE/HL/VI）不公开，WD 部分是公开数据集。
- 模型约 2B + 300M（与 π0 同量级）；显存需求同 π0（据 openpi：推理 >8 GB，LoRA >22.5 GB，全量 >70 GB，未核实）。RTC 论文报告 π0.5 单任务微调约 24 h / 8×H100。8×H100 微调/推理没问题。
- 训练细节：预训练 280k 步 α=0，post-training 80k 步 α=10；图像增强 RandomCrop 95% → Resize → Rotate ±5° → ColorJitter(0.3, 0.4, 0.5)（Appendix E）；τ 采样同 π0（Beta((s−τ)/s; 1.5, 1)，s=0.999）。
- 坑：(1) 本体状态是文本 token，要按 openpi 的离散化方式处理；(2) 推理先解码 subtask 再去噪，两阶段要串起来，且高层用 4 路相机、低层用 3 路；(3) 想跳过高层直接喂指令时，指令粒度要接近 HL 标注（"pick up the cup"），不是总任务。

## 6. 关键引用链

**建立在：** π0（架构与 flow expert）；FAST（离散 token 预训练）；Hi Robot / YAY Robot / SayCan（高层-低层分解）；Embodied CoT（Zawalski et al. 2024）与 chain-of-thought；PaliGemma；OXE；CapsFusion、COCO、Cambrian-7M、PixMo、VQAv2（网页数据）。
**后续：** RTC 以 π0.5 为基座做实时推理；Knowledge Insulation（Driess et al. 2025）把"离散 token 训 backbone + flow expert"改成同步训练并加 stop-gradient；π0.6（模型卡）换 Gemma 3 4B + 860M expert；π*0.6、MEM、π0.7 全部继承 π0.5 的 subtask-then-action 推理结构。
