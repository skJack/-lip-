# 一、开篇可用的钩子

- 一台机器人**连续 13 小时**不间断做浓缩咖啡，成功率 90%+
- 到一个**从没去过的陌生人家里**，折从没见过的衣服，**连续两个多小时无人干预**
- 在工厂里组装真实用于包装的纸箱
- 在最难的任务上，**吞吐量翻倍以上，失败率减半**

**核心反差**：这些不是靠「更大的模型」或「更多的数据」做到的。是靠让机器人**自己练**。

# 二、问题：现在的机器人为什么"练不了功"

## 2.1 现在的做法叫模仿学习（SFT）

人戴着控制器遥控机器人做一遍，系统 50 Hz 记录下画面和动作，模型照着学。

**训练目标只有一句话**：看到这个画面，输出人当时做的那个动作。

这里有个很强的隐含假设：**数据里出现的每个动作都是对的、都值得模仿**。损失函数里没有任何地方能表达"这个动作比那个好"——所有样本一律平等。

## 2.2 天花板一：复合误差（compounding error）

这是模仿学习的**结构性缺陷**，不是数据不够或模型不够大能解决的。

### 概念

模仿学习只教了模型"在**人会进入的状态**下该怎么做"。但模型自己执行时会有微小误差，这些误差会把它推到**训练数据里从没出现过的状态**——而在那些状态下，模型没有任何依据，只能瞎猜；瞎猜又制造更大的偏离，如此循环。

```
第 1 步：偏差一点点   →  状态还在数据分布内，能纠正回来
第 50 步：偏差累积    →  状态开始陌生，动作质量下降
第 200 步：           →  完全没见过的状态，彻底失控
```

### 为什么误差是 T² 而不是 T

直觉上，每步犯错概率是 ε，跑 T 步，总错误应该是 `ε × T`。

**但实际是 `ε × T²`**（Ross, Gordon & Bagnell 2011，DAgger 那篇的经典结论）。

多出来的那个 T 从哪来？**因为一旦偏离，就再也回不来了。**

```
第 t 步犯了错  →  之后的 (T − t) 步全都处在陌生状态里
                → 这一个错误的代价不是 1，是 (T − t)

把所有可能出错的时刻加起来：ε × (T + (T−1) + ... + 1) ≈ ε × T²/2
```

**一句话：模仿学习里，错误不会被"摊薄"，它会被"放大"。**

### 折衣服的具体例子

```
T 恤任务论文给的时限是 200 秒，50 Hz 控制  →  一个 episode 最长上万步
```

人类操作员**从来不会把衣服抓成一团**——所以训练数据里根本没有"衣服皱成团时该怎么办"这个画面。

模型自己跑到第 3000 步时手滑了，衣服散开成一团。这一帧的画面在**几万小时的示范数据里一次都没出现过**。

模型接下来会做什么？它只能输出一个它认为"最像见过的东西"的动作——通常是反复重试同一个抓取，或者干脆卡住不动。然后超时，失败。

> **注意这不是"模型太笨"。哪怕模型完美记住了所有示范，这个问题依然存在——因为答案根本不在数据里。**

### 怎么破

有两条路，π\*0.6 两条都用了：

**① DAgger / 人类干预**：让人在策略执行中途接管，专门在"模型自己会犯的错误状态"下补充正确动作。**注意这类数据只能靠让策略自己跑才能采到**，人类示范里天然不存在。

**② RL**：让模型自己跑，从"这次搞砸了"里学。它不需要人告诉它正确答案，只需要知道结果是好是坏。

> **两者都必须先让策略自己跑起来。** 这就是为什么"从经验中学习"是绕不过去的一步。

## 2.3 天花板二：永远超不过师傅

模型在模仿人，所以最好也就跟人一样快。**它永远快不过遥操作员。**

而这篇论文的主要收益恰恰来自"变快"——论文里 T 恤任务第二轮的提升**几乎全部是速度**，成功率一动没动。

```
SFT 的上限 = 示范数据的水平
RL  的上限 = 奖励函数定义的最优
```

奖励说"每多花一秒扣一分"，模型就会自己去找比人更快的做法。这是结构上的差别，不是调参能弥补的。
# 三、RL 和 SFT 到底差在哪（一个常见误解）

## 常见的说法：区别在于有没有负样本

**这个说法只对一半。**

### 反例一：没有负样本，RL 照样有效

论文里 T 恤任务第一轮成功率就到 90%+，第二轮采的数据里几乎全是成功的。但两轮下来吞吐量总共仍提升了 **50%**——论文原话是第二轮「**主要提升的是吞吐量**」（mainly improves throughput）。

这里几乎没有"负样本"可学。RL 在做的是区分「**快的成功**」和「**慢的成功**」。

更能说明问题的是：**T 恤任务只把最快的 10% 标成"好"**，也就是 90% 的数据被标成"差"——而这些数据里绝大多数是成功的。

> **RL 里的「负」不是「失败」，是「低于这批数据的某个分位数」。**

### 反例二：有负样本，也不等于 RL

- **DPO** 有明确的正负样本对，但没有价值函数、没有时序信用分配
- **DAgger** 完全没有负样本，却解决了模仿学习最大的病——因为数据来自策略自己的分布

## 真正的三层差别

**① 监督信号的来源变了（最根本）**
SFT 的目标由数据给定（模仿这个动作），RL 的目标由 reward 给定（最大化未来回报）。**RL 可以优化一个数据里从没人做到过的目标。**

**② 时序信用分配（RL 独有）**
一个 episode 跑了上万步最后失败了——**是哪一步的锅？** 价值函数把 episode 末尾一个稀疏的成败信号，传播回中间每一步。

**③ 数据分布来自策略自己**
模型自己跑，才会进入自己才会犯的错误状态。

## 一句话对比（可直接引用）

- SFT 问：**人会做什么？**
- SFT+负样本 问：**什么该做、什么不该做？**
- RL 问：**做什么能让未来更好？**

多出来的关键维度是「**未来**」，不是「负」。

# 四、π*0.6 干了什么

## 一句话

> **用一个「还要多久做完」的价值函数，给机器人自己跑出来的每一秒打分；把「这一手比平均水平好」压缩成一个词 `Advantage: positive` 塞进提示词；然后照常做监督学习。测试时永远喂 positive。**

## 它在绕开三个坑

| 坑 | 为什么致命 | 解法 |
|---|---|---|
| flow matching 算不出似然 | PPO 需要 `π_new/π_old` 这个比值，flow 模型给不出 | 不用比值，改成条件监督学习 |
| on-policy 太贵 | 真机一条 episode 200–600 秒 | 攒一批→离线训→再采，旧数据全复用 |
| 真机没有奖励函数 | 仿真的 reward 是代码写的，现实没有 | 人只标 episode 级成/败，逐帧分数自动生成 |

# 五、五个关键设计（可以拆成五个小节讲）

## 设计一：奖励只有三行，但它决定了一切

```
r = 0         最后一步且成功
r = −C_fail   最后一步且失败      （大常数，论文没给具体值）
r = −1        其余每一步
```

不打折扣，所以累加起来：

```
回报 = −（到成功还剩多少步）
```

**「最大化回报」就自动等于「又快又成功」。速度和成功率被压进了同一个数字。**

**C_fail 的作用（反事实推演）**：如果没有它，一条「正在搞砸的 episode 中段」的分数会**高于**「一条成功 episode 的起点」——价值函数将完全分不清终点是成功还是报废。

> C_fail 把「快」和「对」拆成两个正交维度：`−1/步` 管快，`−C_fail` 管对。

## 设计二：一个"倒计时器"，把一句话摊成一万个分数

训练一个网络回答：**「照现在这样，还要多久能做完？」**

怎么练出来的？把成功的录像倒着数帧。一条 32 秒的折衣服录像（1600 帧）：

| 第几帧 | 还剩几帧 | 标签 |
|---|---|---|
| 0 | 1600 | −1600 |
| 800 | 800 | −800 |
| 1600 | 0 | 0 |

**逐帧的价值标签不是人标的，是数出来的。**

**这是整套系统能规模化的根本原因**：一条 200 秒的 episode，人只提供 **1 个 bit**（成/败），这 1 bit 会被自动展开成 **10000 帧的逐帧监督信号**。放大倍数 1 → 10000。

**它还会一个副作用技能**：训好之后回放任意录像，在"衣服掉地上"那一帧，价值会**骤降**。但注意——**这不是标注出来的**，单条 episode 的失败标签是均匀打在每一帧上的。这个定位能力是价值函数**跨整个预训练数据集泛化出来的**：它学会了"什么样的画面是要完蛋的"。

## 设计三：怎么给单独一秒打分（导航 ETA 类比）

**你每天都在做这个计算：**

> 出门时地图说：还要 **20 分钟**
> 你开了 **5 分钟**
> 再看，地图说：还要 **12 分钟**
>
> 20 − 5 − 12 = **凭空赚了 3 分钟**

这就是 **advantage**。放到咖啡上：

> 这一秒前，倒计时说还要 **84 秒**
> 过了 **1 秒**
> 现在说还要 **80 秒**
> 84 − 1 − 80 = **赚了 3 秒** → 这一下做得好

**最容易漏的一项**：很多人直接算「剩余时间的差」，忘了减掉「实际花掉的时间」。漏了之后 advantage 几乎恒为正（时间总在往前走），整套方法直接失效。

> **进步必须跑赢时钟**：光"离终点更近了"不够，得"近得比你花掉的时间还多"。

## 设计四：好的坏的都学，只是各自贴张标签

**学术界原来的做法（AWR）**：好片段权重高，坏片段权重 `e^{-20} ≈ 0`。
→ 那条数据是真机器人花 200 秒跑出来的，**等于白采**。

**这篇论文的做法**：每一段都留着，前面贴一张标签，**两种都学**。

```
片段 1   标签：Advantage: positive
片段 2   标签：Advantage: negative
片段 3   标签：Advantage: negative
片段 4   标签：Advantage: positive
```

上岗时只说一句：**「按 positive 那套来。」**

> 整个训练过程从头到尾就是"看录像模仿"，和 SFT 一模一样。**唯一的区别是每段录像前多贴了一张标签。所有 RL 的复杂性被压缩成了一个词。**

**理论依据**（可选，硬核向）：改进后的策略 π̂ 恰好等于原策略额外条件在 I=True 上。这不是启发式技巧，有单调改进保证，来自 CFGRL / MARWIL。

## 设计五：标签贴在哪里 —— 一个不起眼但要命的细节

机器人干活分两步：**先想**（"我现在要磨豆子"）→ **再动手**。

标签必须贴在这两步**之间**。

**论文对这个位置只说了直接后果**：标签插在子任务文本之后、动作之前，所以**只有动作那部分的似然会带上这个条件**，子任务预测本身不受影响。

**至于贴到最前面会怎样，论文没做这个消融。** 一个合理的猜测是：标签会和子任务预测耦合起来，而推理时永远喂 positive，就可能污染子任务的输出。

> ⚠️ 上面这个"会怎样"是我的推测，不是论文的说法。引用时请标注。

> **位置决定了哪些损失项带上这个条件。** 这是全文最见功力的工程细节。

# 六、完整训练流程（七个阶段）

## 阶段 1：训练预训练价值函数

**数据**：数万小时人类遥操作示范，多机器人平台。
**人工成本**：每条 episode 点一下成/败，**1 个 bit**。
**做法**：把每条录像倒着数帧生成逐帧标签 → 归一化到 (−1, 0) → 离散成 **201 个 bin** → 做 201 类分类，交叉熵。

**关键**：没有 TD、没有 bootstrap、没有 target network、没有 Bellman 迭代。**纯监督学习**，不会发散。论文自己承认这比 off-policy Q 函数"不够优"，但"简单、极其可靠"。

**为什么用分布（201 个 bin）而不是回归一个数**：网络可以说"我觉得还剩 60 秒，但有 5% 的可能会砸锅"。标量回归给不出这个信息。
（诚实提示：论文对这个选择只引用了文献，没给论证，也没做消融。）

**产出**：`V_pre`（670M Gemma 3 backbone）

## 阶段 2：训练预训练策略

**数据**：**同一批**示范数据，不采新的。
**做法**：
1. 定阈值，使约 **30%** 的数据标 positive
2. 每条样本算 advantage：`实际表现 − 价值函数的预期`
3. 二值化成 True/False
4. **30% 概率随机丢掉这个标签**（既替代超参 α，又为推理时的 CFG 做准备）
5. 拼进序列，照常做监督学习

**这一阶段的 advantage 在区分什么**：预训练数据以人类示范为主、**绝大多数是成功的**，所以它主要在区分**快的示范 vs 慢的示范**。
（注：论文的预训练集里确实也含失败 episode——Fig. 4 右侧那条就是从预训练数据集取的失败样本。）

> 同样是人类示范、同样都做成了，快的标 positive，慢的标 negative。普通 SFT 对这两条一视同仁；π*0.6 学到了"快的那种长这样"。

**产出**：`π_pre`，即 π*0.6 基座（4B Gemma 3 backbone + 860M action expert）

**为什么非要在预训练阶段做**：让模型在大规模数据上先把 `Advantage: positive` 这个接口学扎实。下游任务只有几百条真机数据，来不及从零学会"这个词是什么意思"。

## 阶段 3：下游任务 SFT

拿目标任务的示范数据微调，但**把标签全部固定为 True**。

因为标签恒为 True，advantage 完全不起作用，**这一阶段退化成普通的监督微调**。论文说这样比让它自由取值稍好。

**产出**：`π⁰`，第一个能上真机的策略。

## 阶段 4：真机采数据 ← 唯一需要真人在场的环节

让 `π⁰` 在真机上跑。每条 episode 有三种可能：

```
① 纯自主跑完 → 成功
② 纯自主跑完 → 失败（超时 / 掉东西 / 没达标）
③ 中途人类遥操作接管纠正，然后放手继续
```

事后有人看录像，从多个质量维度评判，聚合成一个成/败标签。

**论文实际用的数据量：**

| 任务 | 数据量 |
|---|---|
| T 恤/短裤 | **每轮** 300 条自主，**完全不用干预**，4 台机器 |
| 多样衣物 | 450 评测 + 287 干预（论文只给总量，未说明是否每轮）|
| 装箱 | **每轮** 600 自主 + 360 干预，3 台机器 |
| 咖啡 | 414 自主 + 429 干预（只跑一轮）|

**数据是累积的，不是替换的。**

**关于人类干预的一个诚实提醒（论文原文）**：干预**解决不了所有问题**。理由有三——中途接管本身是破坏性事件；即使专家也无法保证每次质量一致；**干预改善不了"整体速度"这类细微特性**。

> **分工是：干预负责修大错、突破探索瓶颈；自主 rollout 负责调速度和细节。**

这也解释了为什么 T 恤任务干脆不用干预——那个任务的瓶颈是速度，而且策略已经快到人类跟不上、没法接管了。

## 阶段 5：微调价值函数

用累积后的全部数据，**从 `V_pre` 重新微调**（不是从上一轮的价值函数接着训）。流程和阶段 1 完全一样，只是数据变了。

## 阶段 6：微调策略

和阶段 2 同一套代码，三处不同：

**① advantage 公式更精确了**：从"整段蒙特卡洛"换成"往前看 1 秒"。因为数据量从数万小时降到几百条，用得起更贵的算法了。

**② 阈值变了**：约 40% 标 positive。**T 恤任务特殊，只有 10%**——因为那个任务成功率已经顶天，瓶颈是速度，所以只把跑得最快的 10% 标 positive，逼模型追那一档。

**③ 新规则：人类干预的片段强制标 positive**，不管算出来多少。

**干预数据最有价值的地方**（可以单独讲）：

```
帧 2900–3000   机器人自己在犯错     → 算出来是 negative
帧 3000–3600   人类接管纠正         → 强制 positive
```

**画面几乎一样，模型同时看到了错误示范和正确示范。** 这是纯自主探索永远碰不到的对照组。

**关键**：每轮都从 `π_pre` 重新微调，**不是** `π⁰ → π¹ → π²` 接力。变的只有数据集，模型参数每次从同一起点重来。论文的理由是避免多轮迭代的参数漂移。

## 阶段 7：推理

```
1. 输入三张图 + 关节角 + 语言指令
2. 模型自回归吐出子任务文本（"grind the coffee beans"）
3. 强制填入 "Advantage: positive"        ← 唯一的 RL 痕迹
4. action expert 做 flow matching 采样，输出动作块
5. 50 Hz 执行；子任务以更低频率更新
```

# 七、标注粒度：1 个 bit 怎么变成一万个标签

这是整套系统能规模化的**真正原因**，也是最容易被读者忽略的一环。值得单独讲一节。

## 7.1 系统里其实有三层标签

很多人会把它们混成一个东西，其实完全不同：

| 层级 | 是什么 | 粒度 | 谁生成 |
|---|---|---|---|
| **第一层** | 成功 / 失败 | **整条 episode 一个** | **人**（看录像点一下）|
| **第二层** | 逐帧奖励 `r_t`、逐帧回报 `R_t` | 每一帧一个 | 公式自动生成 |
| **第三层** | 逐帧标签 `Advantage: positive / negative` | 每一帧一个 | 价值函数自动生成 |

**人只参与第一层。** 二、三层全自动。

## 7.2 放大倍数：1 → 10000

```
一条 200 秒的 espresso episode
  = 200 秒 × 50 Hz
  = 10000 帧

人提供的信息量：1 个 bit（成 / 败）
系统产出的监督信号：10000 帧 × 逐帧标签
```

**放大 10000 倍。**

如果没有这个机制，你要么得让人逐帧标注（一条 episode 标一万次，完全不可行），要么就只能拿到 episode 级的粗信号（没法告诉模型是哪一步错了）。

> **这个放大倍数，是整篇论文能在真机上跑起来的经济学基础。**

## 7.3 第二层怎么自动生成：数帧数

奖励定义只有三行：

```
r = 0         最后一步且成功
r = −C_fail   最后一步且失败
r = −1        其余每一步
```

累加起来，**每一帧的标签就是"这一帧之后录像还剩多少帧"取负**：

```
R_t = −(T − t)
```

一条 32 秒（1600 帧）的成功折衣服录像：

| 帧 | 还剩几帧 | 标签 |
|---|---|---|
| 0 | 1600 | −1600 |
| 800 | 800 | −800 |
| 1600 | 0 | 0 |

**纯粹的机械操作，一行代码。**

## 7.4 第三层怎么自动生成：价值函数打分

`Advantage: positive/negative` 由价值函数算出来：

```
A = 原本以为还要多久 − 实际花掉的 − 现在还要多久
I = (A > 阈值)
```

关键是：**价值函数本身也是用第二层的标签训出来的。** 所以整条链是：

```
人：1 个 bit
   ↓ 数帧数
第二层：10000 个逐帧回报
   ↓ 训练价值函数
价值函数：会看画面估"还要多久"
   ↓ 隔 1 秒（50 步）的两个价值相减，再减去这 50 步实际花掉的时间
第三层：10000 个逐帧 positive/negative 标签
   ↓ 喂给策略
```

## 7.5 一个必须理解的错位：episode 级 ≠ 帧级

> **成/败是 episode 级的，但 `positive/negative` 是帧级的。前者只是生成 reward 的原料，不是最终标签。**

所以会出现这两种情况：

### ① 成功的 episode 里，大部分帧被标 negative

这不是假设，是论文里真实发生的事：

```
T 恤任务成功率  90%+
但阈值调到只有 10% 的帧标 positive
  → 成功 episode 里的绝大多数帧，标的是 negative
```

含义是：**"你做成了，但你这一段太慢了，别学这个节奏。"**

### ② 失败的 episode 里，可以有帧被标 positive

如果机器人中途手滑，但接着做了一段漂亮的自我纠正，价值函数会看到"还要多久"回升 → advantage 为正 → 标 positive，**哪怕这条 episode 最终失败了**。

（按公式推，失败 episode 最后 50 帧的奖励求和会吃进 `−C_fail`，这一段大概率是 negative；不过 `V(o_t)` 自身也已被 `−C_fail` 压低、两者会部分抵消，具体多负取决于终止态怎么处理，论文没写。）

## 7.6 逐帧的"定位能力"是泛化出来的，不是标出来的

这里有个很容易误解的机制，值得单独点出来。

看奖励公式：一条失败 episode 的**每一帧**都被 `−C_fail` **均匀**压低。

> **所以单看一条 episode，价值函数并不知道是哪一帧出的问题。**

那论文 Fig. 4 里"价值在出错那一刻骤降"是怎么来的？

**是从数万小时、跨任务跨机器人的预训练数据里泛化出来的。** 价值函数学的是一个映射：`画面 → 预计还要多久`。见过足够多数据后，它学到了统计规律：

```
「衣服皱成一团摊在桌上」这类画面       → 后面通常还要很久，甚至做不完
「衣服平整、两个肩角已被捏住」这类画面  → 后面通常很快就完
```

于是回放**任意一条**录像时，在"衣服掉地上"那一帧，它会认出这是个不祥的画面，输出骤降。

> **逐帧的信用分配不是标注出来的，是价值函数跨数据集泛化出来的。** 这是整套方法最漂亮的一环，也是"时序信用分配"这个 RL 核心问题在这篇论文里的具体答案。

## 7.7 为什么这个设计比"让人标得更细"更好

假设你不用价值函数，改成让人标得更细，会怎样？

| 方案 | 人工成本 | 问题 |
|---|---|---|
| 逐帧打分 | 一条 episode 标 10000 次 | 完全不可行 |
| 标关键帧 | 一条标 5–10 次 | 主观、不一致；也说不清"快慢" |
| 标片段好坏 | 一条标几十次 | 成本仍高；且人判断不了"比平均快多少" |
| **RECAP：标 1 个 bit** | **一条标 1 次** | **人只判断结果，机器负责摊到每一帧** |

> **让人做人擅长的事（判断结果好坏），让模型做模型擅长的事（把粗信号摊细）。**

这也解释了为什么论文能收几千条真机数据——如果标注成本高 100 倍，这个实验根本做不起来。
# 八、这个循环为什么会持续变强 ← 最容易被漏掉的一点

**价值函数每轮也在重训，而且是在累积数据上重训。**

而 advantage = 「实际表现 − 价值函数的预期」，价值函数的"预期"就是它见过的所有数据的平均水平。

```
第 1 轮：V 在「示范 + π⁰ 的 rollout」上训
        π⁰ 比较菜 → "平均水平"较低 → 容易拿到 positive

第 2 轮：V 在「示范 + π⁰ + π¹ 的 rollout」上训
        π¹ 已经更强 → "平均水平"上移
        → 同样的动作，这一轮可能就拿不到 positive 了
```

> **每一轮，"平均水平"这条基准线都在往上抬。模型永远在追一个不断上移的标准。**
>
> 不是模型变强了就够了，而是**标准跟着模型一起变强**。

# 九、实验结果（完整版）

## 9.1 先看指标：为什么核心指标是 throughput

论文用两个指标，但**主推第一个**：

**① Throughput（吞吐量）= 每小时成功完成多少次**

它**同时包含速度和成功率**：

```
一小时做 10 杯，成功 9 杯  →  throughput = 9
一小时做 4 杯，成功 4 杯   →  throughput = 4
```

第二个模型成功率 100%，但吞吐量不到第一个的一半。**只看成功率，你会得出完全错误的结论。**

论文主推这个指标，是因为**它最大的收益就来自"变快"**——而变快是 SFT 结构上做不到的事。用成功率当主指标，等于把自己最大的优势藏起来。

**② 成功率**：人工标注。标注员从多个质量维度评判，再聚合成一个成/败标签。

## 9.2 五个任务

| 任务 | 内容 | 时限 |
|---|---|---|
| **折衣服（T恤/短裤）** | 从筐里取出、摊平、折叠、码到桌子右上角 | 200 s |
| **折衣服（多样）** | **11 类**衣物：毛巾、衬衫、毛衣、牛仔裤、T恤、短裤、polo、裙子、长袖、袜子、内衣 | 500 s |
| **折衣服（定向去毛病）** | 单件橙色 T 恤，固定初始条件，**严格标准：领口必须朝上居中** | 200 s |
| **咖啡（双份浓缩）** | 拿手柄→磨豆→压粉→锁进咖啡机→拿杯→萃取→出品，**不能掉手柄、不能洒** | 200 s |
| **装箱** | 工厂真实部署：平板纸板→折成箱→贴标签→放进货箱正确位置 | 600 s |

两个细节：

- **多样衣物任务只报最难的那一项**（扣扣子的衬衫）。论文的理由是"降低指标方差"——但也意味着这个数字**不代表 11 类衣物的平均水平**。
- **咖啡策略实际能力更强**（拿铁、冰美式，甚至用毛巾擦咖啡机），但定量实验只测双份浓缩。

## 9.3 实验设计最聪明的地方：五级对照阶梯

他们没有简单地"我们 vs 别人"，而是搭了一个**逐级递进的阶梯**：

```
① π0.5 预训练                    ← 上一代模型
      ↓ 加了：更大 backbone、更多机器人平台的数据
② π0.6 预训练（纯监督）           ← 新基座，但没有 advantage 接口
      ↓ 加了：advantage conditioning 架构 + 离线 RL 预训练
③ π*0.6 RL 预训练                ← 有接口了，但没针对下游任务微调
      ↓ 加了：用目标任务示范数据微调（标签全 True，即普通 SFT）
④ π*0.6 offline RL + SFT         ← ★ 关键对照组
      ↓ 加了：真机自主 rollout + 人类干预
⑤ π*0.6 完整 RECAP（Ours）
```

**为什么第 ④ 档是关键：** 它已经有了 advantage 架构、离线 RL 预训练、下游示范微调。**唯一没有的，就是「机器人自己跑出来的经验」。**

> **④ → ⑤ 的差距，才是"从经验中学习"的净贡献。**

论文报的所有"翻倍""减半"，**都是相对第 ④ 档说的**，不是相对最弱的 π0.5。这一点很诚实——很多论文会拿最弱的 baseline 说事。

另有两个**策略提取方法**的对照，喂完全相同的真机数据：**AWR** 和 **PPO**。

> ⚠️ **一个容易被忽略的点**：论文里这两个 baseline 都是从 **π0.6**（纯监督预训练、没有 advantage 接口）起步的，而 RECAP 从 **π\*0.6**（做过离线 RL 预训练）起步。所以这个对比里除了算法，还混着「离线 RL 预训练」这一项——**它不是一个纯粹的算法消融**。

## 9.4 结果一：主结果

论文正文的结论：

- **多样衣物**和**浓缩咖啡**上，从 ④ 到 ⑤，**throughput 翻倍以上，失败率约减少一半**
- **简单折衣服**任务上，SFT 之后成功率已接近上限，**但 throughput 仍显著提升**
- **除多样衣物外，所有任务成功率 90%+**

最后一条是关键——90%+ 才是"能真的拿去用"的门槛。

**装箱任务还拆了四个子阶段**：取纸板 → 折箱 → 贴标签 → 放进货箱。RECAP 在**每个子阶段**都最高、且更均衡。

> **一个很有信息量的细节**：论文说装箱任务**大部分失败是超时**，不是做错。瓶颈是速度不是能力——这正好解释了为什么直接优化速度的 RECAP 在这个任务上收益大。

## 9.5 结果二：多轮迭代（最能说明问题的实验）

**T 恤/短裤 —— 故意只用纯自主数据，不用任何人类干预**

```
每轮 300 条 episode，4 台机器，跑两轮
→ throughput +50%
→ 成功率第一轮就到 90%+，第二轮几乎全是提速
```

**为什么故意不用干预？** 论文明说是为了检验"**RL 单独能带来多少提升**"，排除"人类手把手教"的贡献。这是个很干净的对照。

论文还给了个有意思的理由说明这个任务为什么没法用干预：**策略已经快到接近人类操作员的速度，人跟不上、没法接管。**

**装箱 —— 自主 + 干预**

```
每轮 600 自主 + 360 干预，3 台机器，跑两轮
→ throughput 2×
→ 第一轮先降后升（论文没解释为什么会降）
→ 成功率两轮持续提升，最终折箱和贴标都约 90%
→ 剩余失败主要在最后把箱子码到堆上那一步
```

## 9.6 结果三：advantage conditioning vs AWR vs PPO

用 T 恤任务对比，**喂完全相同的数据**。

论文特意说明：**这批数据其实对 baseline 略有利**——因为它是跑 RECAP 时收集的，质量比 baseline 自己能收到的更好。

| 方法 | 表现 |
|---|---|
| **AWR** | 成功率还行，但**策略慢很多**，throughput 低 |
| **PPO** | 必须用**极小信赖域（η = 0.01）**才能在这种 off-policy 设定下稳定。稳是稳了，但效果不好 |
| **RECAP** | throughput 远高于两者 |

论文的原话是：两个 baseline 都"**难以超过 offline RL + SFT 这个起点**"。

> 翻译一下：**同样的几百条真机数据，换成 AWR 或 PPO，基本等于白采。**

PPO 那句"必须极小信赖域才能稳定"也很说明问题：它在离线设定下**被迫保守到几乎不动**，所以学不到东西。

## 9.7 结果四：能定向去除一个特定毛病吗

```
任务：折单件橙色 T 恤
严格标准：领口必须居中朝上
对抗性初始条件：故意把衣服摆成让第 ④ 档策略经常折错的样子
数据：两轮，每轮 600 条
结果：成功率 97%，而且速度快
```

**意义**：**换一个标注标准，就能定向改变策略行为，不用改任何代码。** 对实际部署很有价值——客户说"我要领口朝上"，不需要重新设计奖励函数，只要告诉标注员换个勾选标准。

> ⚠️ **但这里有个坑**：正文说这个实验"完全通过 RL，不用任何干预数据和额外示范"，附录却明确写着收了 **280 + 378 条干预 episode**。**论文自相矛盾。引用这个 97% 时不要说"纯 RL 做到的"。**

## 9.8 部署证据（不是数字，但可能最有说服力）

- **连续 13 小时**不间断做浓缩咖啡
- 在一个**从没去过的家里**，折**从没见过的**衣物，连续 **2 小时以上**无人干预
- 装配**工厂里真实用于包装**的纸箱
- 配套视频有多个任务的多小时 time lapse

> **为什么这个比表格更有说服力**：实验室的百次评测可以挑条件，13 小时连续运行挑不了——任何一次卡死、掉件、软件崩溃都会暴露。

## 9.9 这些实验证明了什么、没证明什么

**证明了**

- 在**同样的真机数据**下，advantage conditioning 明显优于 AWR 和 PPO
- 「从自主经验中学」的净贡献是实打实的（因为有第 ④ 档做对照）
- **纯自主数据**（无人类干预）也能带来提升——T 恤那个实验很干净
- 主要收益来自**速度**，而速度是 SFT 结构上拿不到的
- 换标注标准就能定向改行为

**没证明 / 缺口**

- **几乎没做方法内部的消融**：201 个 bin vs 标量回归没比；N=50 vs 其他 lookahead 没比；30%/40%/10% 阈值的敏感性没比；30% dropout 率没比；**干预数据 vs 纯自主数据各自贡献多少没拆开**
- **评测样本量论文正文没明确交代**。只说误差棒是 standard error，但每个数据点跑了多少条 episode 没写清
- **评测和数据采集是同一批 rollout**（比如多样衣物"450 条评测 episode"同时进了训练集），评测集不独立
- **成功率是人工标注的，标准可调**，跨论文不可比；throughput 也受时限影响，而时限是论文自己定的
- **没有和其他实验室的 VLA 比**。所有 baseline 都是 PI 自家模型（π0.5、π0.6）

```
1.  90%+     除多样衣物外所有任务的成功率  ← "能用"的门槛
2.  2×       最难任务的吞吐量提升，失败率减半
3.  13 小时  连续做咖啡不中断             ← 最难造假的那个数
```

# 十、RECAP 和其他强化学习方法的差别（技术定位）

## 10.1 一句话说清核心差异

> **绝大多数 RL 方法把"好坏"编码进 _梯度_；RECAP 把"好坏"编码进 _输入_。**

这一条差异衍生出后面所有的不同：

```
编码进梯度  →  需要似然或权重  →  ① flow 模型算不出似然，用不了
                                  ② 坏数据被权重抹掉，等于白采

编码进输入  →  只需要能拼进序列  →  ① 任何生成模型都能用
                                  ② 所有数据一律平权，一条不浪费
```

## 10.2 策略提取这一维

策略提取 = 「有了价值函数，怎么变成一个更好的策略」。这是 RECAP 唯一动刀的地方。

| 方法 | 怎么把 advantage 传给策略 | 硬伤 |
|---|---|---|
| **PPO**（比值/信赖域）<br>**SAC**（重参数化梯度）| 前者靠 `π_new/π_old` 比值，后者靠可微分的采样路径 | 都需要能算动作似然或可微采样。flow matching 没有可直接计算的似然，**只能退到扩散似然的近似上，难以规模化到大 VLA**；PPO 还必须 on-policy |
| **AWR / CRR / IQL**（加权回归）| 给每条数据一个权重 `exp(A/β)` | 坏数据权重 `e⁻²⁰ ≈ 0`。**真机跑 200 秒采来的数据，梯度贡献是零** |
| **RECAP**（advantage conditioning）| **把 advantage 二值化成一个 token 塞进 prompt** | 所有数据权重都是 1，一条不丢 |

论文用完全相同的真机数据做了这个对照，结论见 9.6。

## 10.3 价值函数这一维

| | 主流 RL | RECAP |
|---|---|---|
| 学什么 | `Q(o, a)` | `V(o)` |
| 怎么学 | TD / Bellman bootstrap | **纯蒙特卡洛** |
| 需要 target network | 是 | **否** |
| 会发散吗 | 会，需要各种稳定技巧 | **不会**，本质是监督学习 |
| 输出形式 | 标量 | **201 个 bin 上的分布** |

论文自己承认：*"虽然这个 on-policy 估计器不如经典的 off-policy Q 函数最优，但我们发现它简单、极其可靠。"*

**代价是什么？**（最值得理解的一点）

Bellman bootstrap 能做一件蒙特卡洛做不到的事——**拼接（stitching）**：把 A 轨迹的前半段和 B 轨迹的后半段拼成一条比两者都好的路径。

蒙特卡洛做不到。它只能忠实估计"采数据那个策略平均有多好"，**没法凭空组合出数据里不存在的行为**。

**RECAP 怎么补偿的？** 靠**迭代**：

> **它不用 bootstrap 在算法内部做策略迭代，而是用「重新采数据」在算法外部做策略迭代。** 慢，但绝对不会发散。

## 10.4 和其他"VLA + RL"工作的对比

论文 related work 点名了四类前作：

**第一类：直接把 PPO 用在 VLA 上**
PPO 是 on-policy，真机每次更新都要重采几百条。论文评价是"难以以高效可扩展的方式推广到真实世界"。这些工作基本都在**仿真**里。

**第二类：在冻结的 VLA 之上套一层 RL**

| 做法 | 代表 |
|---|---|
| 训一个残差策略叠在 VLA 输出上 | Guo 2025、Xiao 2025 |
| 只微调 action head 网络 | ConRFT |
| 对 VLA 提出的候选动作做筛选/精修 | Policy-Agnostic RL、Steering、ATE |
| 在扩散 VLA 的**噪声空间**里优化 | **DSRL** |

共同点：**VLA 本身不动**，RL 在外面套一层。
RECAP 的差异：**端到端训练整个 VLA**（4B backbone + 860M action expert 全都更新）。

论文那句关键的话：*"这些先前工作通常使用离散动作或简单的高斯连续动作分布。"* 它们是**为了能算似然，被迫牺牲了模型表达力**。

**第三类：价值函数 + 真机端到端 RL（最接近的一类）**

| 工作 | 做法 | 和 RECAP 的差别 |
|---|---|---|
| **CO-RFT** | calibrated Q-learning，离线示范，抓取任务 | **没有在线改进阶段** |
| **GRAPE** | DPO 从人类偏好优化 pick-and-place | 偏好学习不是价值函数；任务简单 |
| **VLAC** | PPO + time-to-completion 价值函数 | on-policy，离散动作 |
| **Ghasemipour 2025** | REINFORCE + time-to-completion | 同上 |

**任务复杂度的差距**（论文明确对比了）：

```
前作的任务：移动一个碗、展开一张垫子、在桌面推物体
RECAP：    5–15 分钟的多阶段任务，可形变物体、液体，
          200–600 秒时限，13 小时连续运行
```

> 这可能是最实在的差异。前面那些方法不是不能用，是**没人在这个复杂度上验证过**。

**第四类：条件式 RL（RECAP 的直系祖先）**
Upside-Down RL、Decision Transformer、RvS、Reward-Conditioned Policies、CFGRL。RECAP 就站在这一支上，差别是**规模和落地**。

## 10.5 和 CFGRL 的差异（论文脚注明确点出的核心改动）

CFGRL 是 RECAP 数学上的直接来源。**论文脚注明确点出的核心差异**是：

| | CFGRL | RECAP |
|---|---|---|
| 阈值 ε | 统一取 **0** | **按任务的分位数**（30%/40%/10%）|
| 保守 vs 激进怎么调 | 测试时调 **β** | **训练时调 ε** |

论文给的理由（写在脚注里）：

1. **高 β 会把动作分布推到支撑集边缘** → 动作变得过于激进
2. **β 管不到模型的自回归部分**（只影响扩散采样）

> 这个改动看着小，但是让方法能在真机上跑的关键之一——"动作过于激进"在仿真里是个数字，在真机上是砸坏的咖啡机。

## 10.6 诚实拆解：什么是借来的，什么是新的

论文自己在 intro 最后说得很清楚：*"虽然各个算法组件在先前工作中都被探索过，但这种特定的组合方式是新的。"*

**借来的：**

| 组件 | 出处 |
|---|---|
| advantage conditioning | Kumar 2019、Decision Transformer、Upside-Down RL |
| 改进保证的定理 | MARWIL、CFGRL |
| 分布式价值函数（201 bin）| Bellemare 2017 |
| 人类干预 (HG-DAgger) | Kelly 2019 |
| Knowledge Insulation | Driess 2025 |
| FAST 动作 tokenizer | Pertsch 2025 |

**真正新的：**

1. **这个组合本身**
2. **阈值 ε 代替测试时 β**（相对 CFGRL 的实质改动）
3. **在预训练阶段就引入 advantage conditioning**——大多数工作只在 post-training 做 RL
4. **统一处理四种异构数据**：示范 + 旧策略 rollout + 新策略 rollout + 人类干预，全走同一个目标函数
5. **首次在这个任务复杂度上跑通**

## 10.7 RECAP 放弃了什么（判断它适不适合你的关键）

一个方法的特点，一半在它做了什么，一半在它**故意不做什么**：

- **❌ 放弃了 stitching**：蒙特卡洛没法把不同轨迹的好片段拼起来。**数据里如果压根没有好动作，再怎么算也提取不出来。**
- **❌ 放弃了探索**：论文承认"探索基本是贪心的"。它假设初始模仿学习策略**已经能做出合理动作**。冷启动场景帮不上忙。
- **❌ 放弃了在线**：是"攒一批→离线训→再采"，不是边跑边学。
- **❌ 放弃了全自动**：奖励标注、人类干预、场景复位全靠人。

## 10.8 一张总表

| 维度 | 主流做法 | RECAP |
|---|---|---|
| 好坏信号走哪条路 | 梯度 | **输入序列** |
| 策略提取 | 策略梯度 / 加权回归 | **条件化** |
| 动作表示 | 离散 / 高斯 | **flow matching，端到端** |
| RL 加在哪一层 | VLA 之上套一层 | **整个 VLA** |
| 价值函数 | Q，TD bootstrap | **V，纯蒙特卡洛** |
| 数据范式 | on-policy / offline | **iterated offline** |
| 数据来源 | 单一 | **四种异构，统一处理** |
| RL 引入时机 | 只在微调 | **预训练就引入** |
| 坏数据的命运 | 被降权 ≈ 丢弃 | **平权参与，贴 negative 标签** |
| 稳定性风险 | 高（发散、崩溃）| **低，本质是监督学习** |
| 换来的代价 | — | 无 stitching、无探索、不在线、不自动 |

## 10.9 一句话定位（适合做视频结论）

> **RECAP 不是一个更强的 RL 算法，而是一个把 RL 塞进大模型监督学习流程的接口设计。**
>
> 代价是放弃了 RL 理论上的很多能力（拼接、探索、在线），换来的是「在 40 亿参数的 flow matching VLA 上真的能跑、真的不崩、真的能上工厂」。
# 十一、软肋与存疑（自媒体最需要的"但是"部分）

## 论文自相矛盾

正文说"定向去除毛病"那个实验是 **"完全通过 RL，不用任何干预数据和额外示范"**，但附录明确列出 **280 + 378 条干预 episode**。

**在澄清前，不要引用"完全无干预"这个结论。**

## 正文和附录对阈值的定义打架

正文说取「价值函数**预测值**的 30% 分位」，附录说「调阈值使约 30% 的数据 **advantage 为正**」。两者对象不同、方向相反。要复现的话**按附录**。

## 论文没说清的

- `C_fail` 的数值、归一化的确切公式，都没给
- 主结果里哪些用了推理期增强技巧（CFG），没说明
- 装箱第一轮吞吐量先降的原因，未作解释
- 用分布式价值函数只引用了文献，**没给论证也没做消融**
- 预训练数据里失败样本的来源和比例，完全没交代

## 作者自己承认的局限

1. **系统不全自动**——奖励标注、人类干预、**场景复位**全靠人
2. **探索是贪心的**——只靠策略自身的随机性和人类干预，没有主动探索机制
3. **不是真正的在线 RL**——是"攒一批→训→再采"，不是边跑边学

> 说人话：**这套系统还是需要一屋子人陪着机器人练。** 论文在 Discussion 收尾处也承认，让 RL 成为 VLA 训练的实用工具"还需要更多研究"。

# 十二、可以直接用的比喻和金句

**比喻**
- 价值函数 = 导航软件的 ETA（预计到达时间）
- advantage = 你开了 5 分钟，ETA 少了 8 分钟 → 赚了 3 分钟
- advantage conditioning = 给每段录像贴"这是做得好的/这是做砸的"，两种都看，上岗时只演好的
- AWR（旧方法）= 看录像时把做砸的部分直接快进跳过 → 那段真机器人跑出来的数据白采了

**金句**
- 「所有 RL 的复杂性，被压缩成了提示词里的一个词。」
- 「人只提供 1 个 bit，系统自动展开成 10000 帧的监督信号。」
- 「进步必须跑赢时钟——光离终点更近不够，得近得比你花掉的时间还多。」
- 「不是模型变强了标准就够了，而是标准跟着模型一起变强。」
- 「RL 里的『负』不是『失败』，是『低于平均』。」
- 「π*0.6 相对 π0.6 的全部改动，就是在序列里插了一句话。」
- 「模仿学习里，错误不会被摊薄，它会被放大——一步走错，剩下的几千步全在陌生地带。」
- 「人类操作员从来不会把衣服抓成一团，所以数据里根本没有『衣服皱成团时怎么办』。」
- 「人只判断结果好坏，机器负责把这个判断摊到每一帧上。」
- 「成/败是整条录像一个标签，positive/negative 是每一帧一个标签——这两件事经常相反。」
- 「逐帧的信用分配不是标注出来的，是价值函数跨整个预训练数据集泛化出来的。」
- 「RECAP 不是一个更强的 RL 算法，是一个把 RL 塞进监督学习流程的接口设计。」
- 「大多数 RL 把好坏编码进梯度，RECAP 把好坏编码进输入。」

**适合画的图**
1. 一条价值曲线，成功的平稳上升 vs 手滑那一刻的骤降
2. 导航 ETA 的三个数字：20 − 5 − 12 = 3
3. 输入序列排布图，标签卡在"想"和"做"之间
4. 七个阶段的流程图，标出哪一环需要人
5. 成功 episode 里大部分帧被标 negative 的反直觉对比
6. 复合误差示意：一条轨迹从数据分布里慢慢漂出去，越漂越远
7. 三层标签的漏斗图：人给 1 个 bit → 10000 帧奖励 → 10000 帧 positive/negative

# 十四、一分钟版本（适合做开头或结尾）

1. 机器人现在靠"看人做一遍然后模仿"来学，问题是它永远快不过师傅，也没见过自己会犯的错。
2. 想让它自己练，就得能给它的每一个动作打分。但人只能说"这一整遍行不行"，而一遍有上万个动作。
3. π*0.6 的办法：训一个"还要多久做完"的倒计时器，把一句话摊成一万个分数。
4. 打分方式就是导航的 ETA——开了 5 分钟 ETA 少了 8 分钟，就是赚了 3 分钟。
5. 然后把分数压成一个词贴在录像上，好的坏的**都学**，上岗时只说"按好的那套来"。
6. 结果：吞吐量翻倍，失败率减半，连续 13 小时做咖啡不停。
7. 但这套系统仍然需要一屋子人陪着机器人练——**这才是它离"真正自主"最远的一步。**
