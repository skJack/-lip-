## 补充：采样（从噪声恢复 x₁）的公式

连续形式是解一个 ODE：dx/dt = v̂(x, t)，从 x(0) = ε 积分到 t=1。
实际用欧拉法离散，每步就一行（H3 约定 t=0 噪声 → t=1 干净）：

```
x_{t_{k+1}} = x_{t_k} + (t_{k+1} − t_k) · v̂(x_{t_k}, t_k)
```

即：**新位置 = 当前位置 + 步长 × 模型报的速度**。从 x_{t_0}=ε 出发，
沿 t_0=0 < t_1 < … < t_8 = 1 走 8 步到 x₁，再交给 VAE 解码。

两个自洽性验算：
- 若世界上只有一条直线（模型输出恰为真速度 x₁−ε），一步走完：
  ε + 1·(x₁−ε) = x₁ ✅
- 从任意中间点 x_t 一步跳完剩余路程：x_t + (1−t)·(x₁−ε)
  = t·x₁+(1−t)ε + (1−t)x₁ − (1−t)ε = x₁ ✅
  ——公式没问题；多步的必要性完全来自"模型报的是平均方向"，与口播第 7、8 页的论证一致。

**8 个 t 不是均匀排的**：H3 权重目录里 `scheduler/scheduler_config.json` 写着
`MiniMaxH3Scheduler, shift=12.0`（视频）、`audio_scheduler/…` 写着 `shift=3.0`（音频），
下载的权重里已核对。这是 SD3 式 timestep shift：
σ' = s·σ/(1+(s−1)·σ)（σ 为噪声占比），s 越大采样点越向高噪声段挤——
也就是：视频把步数集中在高噪声段打草稿，音频走得更匀。✅

**步长怎么算**：开跑前一次算好、生成过程中固定不变（不看画面内容、不自适应）。
做法：σ（噪声占比）先均匀取 8 格，过 shift 公式，再换回 t，相邻两点的差就是步长。
按 shift=12 / shift=3 实算（σ 均匀网格 + σ'=sσ/(1+(s−1)σ)，与 diffusers
FlowMatchEuler 家族同款；我拿到的 H3 代码里没有 MiniMaxH3Scheduler 的 .py，
网格约定按 diffusers 惯例推断，形状结论不受影响）：

```
视频 shift=12:
 t 序列: 0 → .012 → .027 → .048 → .077 → .122 → .200 → .368 → 1
 步长Δt:   .012  .015  .021  .029  .045  .078  .168  .632
音频 shift=3:
 t 序列: 0 → .045 → .100 → .167 → .250 → .357 → .500 → .700 → 1
 步长Δt:   .045  .055  .067  .083  .107  .143  .200  .300
```

视频前 7 步全挤在 t<0.37 的高噪声段（最小步长 0.012），最后一步直接跳 0.632——
高噪声段方向最不确定，小步多问；越接近成品方向越准，敢迈大步。音频明显更均匀。
和上面那句定性描述一致。✅

## Q&A 备忘（评论区可能会问）

**Q：训练时体现"8 步"吗？t 是从那 8 个点里采样吗？**
A：不。训练的 t 是 [0,1] 连续随机采样，模型学的是整个连续速度场 v̂(x,t)；
8 步是推理时解 ODE 的离散化选择，可以随时换成 4/20/100 步，不用重训。
证据：① 同一次前向里视频行、音频行、条件行的 t 各不相同且任意取值，
离散训练做不到；② 官方推理接口允许改步数和 flow_shift。
细微处：训练抽 t 的**分布**通常不均匀（往高噪声段偏，SD3 的 timestep 加权），
与推理 shift 思想同源——但那是密度偏好，不是点的绑定。H3 训练代码未开源，
具体分布不可考。
